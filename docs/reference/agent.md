# `agent/` - the BaseAgent turn loop, model adapters, verification and orchestration

`base_agent/` is the single-task runtime: one `BaseAgent.run` is a bounded loop of context projection, one model turn, and governed tool execution until the model returns an accepted final answer or the run is blocked, failed, cancelled or out of iterations. `model.py` defines the provider-neutral model contract; `openai_compatible/` implements it (plus embeddings and vision) over Chat Completions. `verification.py` holds named, host-registered output gates. `runtime.py` wires durable stores around an agent, `task_runner.py` runs one task from caller-supplied model, tool, permission and limit parameters (the MCP `run_agent_task` tool), `graph_agent_executor.py` runs agents as graph nodes, and `orchestrator/` compiles a user policy and an already-proposed plan into a controller-governed multi-agent graph. Model output is always treated as untrusted proposals.

**Role in the workflow.** Per iteration: check the run deadline and cancellation; project context (compact episodes, select observations); project the bounded project state; enforce the three budget guards; call the model under a watchdog; validate the response as an `AgentTurn`; then act on it. A `blocked` turn ends BLOCKED; a `final` turn is validated and optionally gated; a tool turn runs a governed batch whose results become observations, episodes and project-state transitions. Every exit goes through `_terminate`, which records the agent result in project state, seals the profile, emits telemetry and audit entries, and builds the `AgentResult`. An instance runs one task (its profiler allows a single run). A cancellation token does more than stop the loop between iterations: it is raced against every awaited model call, tool call, hook and verification gate, so cancelling interrupts a call that is still running.

**Algorithms & invariants.** Failure handling summary: a transient provider error is retried: the failure becomes an `agent-error` observation and a `model-turn-retrying` event, the run sleeps with exponential backoff (honouring `Retry-After`, capped by `transient_retry_max_seconds`) and the turn repeats at the cost of one iteration; any other model error, a watchdog timeout (`WATCHDOG_MODEL_TIMEOUT` and its tool and verification counterparts), an undeclared tool and a verification rejection end FAILED immediately; invalid tool arguments and unavailable consumed episodes are recoverable failed results the model can correct; a denied or blocked tool ends BLOCKED. The three guards are CONTEXT_DEADLOCK, PROJECT_STATE_BUDGET_EXCEEDED and CONTEXT_BUDGET_EXCEEDED (all BLOCKED). Graph episode ids and episode-store ids are assumed to coincide (both sequential), which holds only for a fresh store. Cancellation is cooperative at the token and forceful at the await: the token is polled, not signalled, so a cancel is noticed within 50 ms, and the interrupted operation receives `CancelledError` at its next await. A blocking call run on a thread cannot be stopped from outside; the OpenAI-compatible adapter runs its request on a detached daemon thread (`foundations/detached.py`), so the run ends at once and the request finishes, or times out, on its own. A tool that is interrupted may already have had side effects.

**Algorithms & invariants.** A run is a telemetry run id (a task id): its events and metrics, its audit transcript and the journal files recorded under it. A run is pruned whole or not at all, because removing a prefix would break its hash chain. It qualifies when it has an `agent.terminated` event (or the policy says `include_unfinished`), its last event is older than `older_than_seconds`, it is not among the `keep_most_recent` newest, and both chains verify; a run with a broken chain is reported and left, as evidence. Nothing is deleted without a policy from the caller: no threshold is built in. Order matters for crashes: the tombstone is written first, then the journal, the audit files and the telemetry rows, so the run stays discoverable by its telemetry until the last step and a second pass finds the tombstone by run id, telemetry sequence and head hash and finishes the job without writing another. The tombstones form their own hash chain (`.agent-retention/tombstones.jsonl`), appended under `.agent-retention/retention.lock`, so editing or dropping one is detectable; a tombstone is the only record of a pruned run's final heads and tool-result hashes, which is what lets `verify-evidence` keep vouching for project-state evidence whose journal file is gone. A run that is revived between examination and deletion is caught by the telemetry sequence check under the store's write transaction (`TELEMETRY_RUN_CHANGED`); an event arriving after the last check but before the final delete is the one unguarded window, which is why `older_than_seconds` should be far longer than any task's resubmission delay. Journal handle numbers are never reused (`.high-water`). Not pruned: project states, graph runs, controllers, orchestrations, episode records, exported reports, workspaces and journal files recorded without a run id. The bytes a report counts are the logical size of what was removed. The audit and journal files are deleted outright; the telemetry database reuses the pages its deleted rows held, so it stops growing, but its file does not shrink until a `VACUUM`, which needs a quiet store and is left to the operator.
